# Kora · 你的生活搭子 / Your everyday companion

团队讨论用前端原型 v0.6（2026-10-19）。核心体验：中断后还能继续；先选一只合拍的 Kora，再建立自己的生活档案。

## 当前功能

- 中文 / English 切换覆盖首次设置、五个功能页、弹窗、提示、性格台词与预设聊天回复。用户填写的昵称和聊天原文不自动翻译。
- 首次进入先选性格，再填写昵称、身高、体重、运动偏好、可用时间和生活目标；保存后进入首页，同一份资料可在档案里修改。
- 四种运动装 Kora：淡淡型 Chill（绿色）、毒舌型 Witty（深灰）、暴躁型 Fiery（暖橙）、温柔型 Gentle（粉色）。性格影响问候、情境回复、完成反馈与少量强调色。
- 五页：今天（计划、周历、调整 / 撤销）、饮食（六种示例食物与记录）、运动（筛选与替换计划）、聊聊（双语情境回复）、档案（性格、资料与本地数据管理）。
- 周历按设备本地日期展示，支持上下周浏览和每日详情；计划、餐食、完成状态及调整记录按日期保存。跨天后保留过去的记录。
- 调整计划前展示确认步骤；改到明天会预约真实的次日，包括跨周、跨月情况。已有目标日安排不会被覆盖；撤销也会保护目标日后续新增的数据。
- 所有性格都遵循同样的边界：不羞辱身材，不鼓励补偿性节食或忍痛训练；受伤情境使用统一的认真回应。

## 当前视觉与动作

中文展示标题使用本地站酷小薇，正文使用系统中文字体；英文与数字使用本地 Manrope，英文展示标题使用设备 Georgia 衬线字。保留白底、留白、顶部导航与手机底部导航。布局研究参考 [Apple 健康页面](https://www.apple.com.cn/health/)，未复制其素材或下载专用字体。

团队的独立字体方案 `typography.css` 保留供比较与追溯，当前 `index.html` 不加载它；页面采用上述已确认的排版。

- 当前角色图为 `kora-calm-sport-v2.png`、`kora-gentle-sport-v2.png`、`kora-snark-sport-v4.png`、`kora-fiery-sport-v4.png`，使用修订后的短腿、小脚掌与收拢坐姿。
- 首页通过 GSAP 时间线和 WebGL 局部变形实现呼吸、眨眼和单耳动作。呼吸横向幅度为3%，周期6秒；耳动首次在12秒出现，之后间隔20 / 24秒，单次动作约0.8秒。保留用户已认可的眨眼效果。
- 闭眼素材只在眼睑附近采样；「打个招呼」触发回应，「暂停动作」恢复静态原图。WebGL 或素材不可用时回退为原图。
- 首页标题分行进入并展开弧线，性格卡片悬停 / 键盘聚焦时轻微抬起。系统减少动态效果时使用静态呈现；陪伴动作在后台或离开视口时暂停，切页时释放相关资源。

## 数据与实现边界

这是可点击的前端原型，没有账号登录、后台、真实 AI、云端同步或用户间数据共享。首次设置是浏览器本地流程，不是账号注册；聊天是预设情境演示。

`localStorage` 使用存储键 `kora.preview.v1`，当前数据结构为 **schema 3**，保存资料、语言、按日计划、餐食和调整记录。兼容团队 schema 2 的按日记录，以及旧 schema 1 / 2 的无日期记录。无日期计划与餐食完整保留在独立旧记录存档中，不猜测日期或自动计入今天；原有资料继续保留，缺少必要信息时需要补齐首次设置。

聊天仅保留在当前页面内存中；未提交的资料草稿在同页切换语言或返回上一步时保留，刷新后不保留。清除浏览器数据或更换设备后，本地记录不会随账号恢复。保存失败会提示“本次页面保留”。多标签页并发修改的自动合并尚未实现；回退旧版代码前应保留存储副本。

食物数值和训练卡片是演示内容；运动外链指向作者频道，并非逐条核验过的训练视频。运动偏好作为档案记录，不代表完成了个体适用性评估。身高、体重不用于生成减重处方、目标体型、减重期限或自动改变考拉体型。

提醒仅为页面文字，没有系统通知。尚未实现社群、照片评估、开放式 AI 对话及自动体型联动。

## 本地运行

无需安装依赖或构建。在仓库根目录执行：

```sh
python3 -m http.server 4179 --bind 127.0.0.1 --directory website
```

打开 http://127.0.0.1:4179 。独立 ZIP 包请解压后，在 `website/` 内执行 `python3 -m http.server 4179 --bind 127.0.0.1`。

图片、GSAP 和本地字体均随代码提供；外链作者频道需要联网。请使用 HTTP，避免 `file://` 的存储差异。

## 演示路线

1. 选粉色温柔型 → 填写虚构演示资料 → 保存 → 首页出现选中的 Kora。
2. 档案里确认资料同步；换毒舌型并保存 → 首页与聊天同步换语气。
3. 聊天输入“今天只有10分钟” / “I only have 10 minutes” → 查看可选安排 → 对比并确认 → 首页与周历同步 → 撤销。
4. 浏览上一周 / 下一周，点击日期查看记录；改期前确认目标日已有安排会得到保护。
5. 切换中文 / EN 并刷新，确认语言、性格和已保存资料保留。
6. 档案 → 清除本地数据 → 二次确认 → 回到首次选择流程。

## 代码与验证

- `app.js`：双语文案、四种性格、页面、资料与计划交互。
- `daily.js`：本地日期、按日记录、迁移、跨日改期与撤销保护。
- `companion.js`：首页陪伴动画、静态回退及资源清理。
- `styles.css`：当前排版、性格选择与响应式布局。
- `ASSETS.md`：素材来源、许可与候选素材状态；生成提示词位于 `assets/persona-*-prompts.json` 等文件。
- `SHA256SUMS.json`：网站文件校验清单，不包含清单自身。
- `QA.md`：各版本验证记录及未验证范围；当前状态参见 v0.6 部分。

在仓库根目录运行现有检查（需要 Node.js）：

```sh
node --check website/app.js
node --check website/companion.js
node --test website/daily.test.cjs
node website/tests/state.test.cjs
node website/tests/companion.test.cjs
node website/tests/merge.test.cjs
```

现有测试覆盖日历边界、改期与撤销、双语状态、资料验证、数据迁移及实际 GSAP 时间线。v0.6 已进行桌面浏览器主要流程检查；动画观感依据用户实看反馈，静态截图和自动测试不代替完整跨浏览器、真机或性能验收。

## 协作与合并

本原型在 `Cora` 分支维护，v0.6 已推送；包含队友 PR #2 的每日记录功能及 PR #3 的独立字体方案文件，当前字体启用情况见上文。更新直接进入现有 `website/` 目录，不另建版本目录，ZIP 不提交到仓库。

通过 `Cora → main` 的 PR 提交审核。合并须经 Cora 明确批准；创建 PR 不代表已合并，也不代表网站已部署。
